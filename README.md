# checker-site

Мониторинг доступности списка сайтов (HTTP GET + опционально ICMP-пинг).

## Возможности

- Проверка по HTTP GET (2xx/3xx = UP) в параллельных потоках (до 32 воркера)
- ICMP-пинг (3 пакета) параллельно с HTTP — флаг `--icmp` (не влияет на UP/DOWN)
- Вывод резолвнутого IP рядом с хостом
- Обнаружение VPN-интерфейса и его IP (через `ip addr`)
- Системная информация в заголовке: OS, пользователь, hostname, локальный IP, VPN
- Табличный вывод с цветами (ANSI, отключается для не-TTY)
- Динамическое обновление таблицы на месте (без скролла) в циклическом режиме
- Блок "Причины недоступности" под таблицей (HTTP-статус, сервер, тело ошибки)
- Уведомление об изменениях статуса (up → down / down → up) между проверками
- Циклический мониторинг или однократная проверка
- Отчёт в файл для техподдержки (`--log`)

## Запуск

```bash
# Однократная проверка
python3 checker.py --once https://example.com https://httpbin.org

# Мониторинг по файлу, интервал 60 сек
python3 checker.py -f sites.txt --interval 60

# С ICMP-пингом и таймаутом 5 сек
python3 checker.py -f sites.txt --interval 30 --timeout 5 --icmp

# Сохранение отчёта в файл (для техподдержки)
python3 checker.py -f sites.txt --log report.txt

# Всё вместе
python3 checker.py -f sites.txt --interval 30 --icmp --log /tmp/monitor.log
```

## Аргументы

| Флаг | Описание | По умолчанию |
|---|---|---|
| `urls` (позиционный) | URL(ы) для проверки | — |
| `-f`, `--file` | Файл со списком URL (по одному на строку) | — |
| `-i`, `--interval` | Интервал между проверками, сек | 60 |
| `-t`, `--timeout` | Таймаут HTTP-запроса, сек | 10 |
| `--once` | Один раз, без цикла | выкл |
| `--icmp` | ICMP-пинг (3 пакета) параллельно с HTTP | выкл |
| `--log FILE` | Сохранять отчёт в файл (plain text) для техподдержки | — |

## Отчёт для техподдержки (`--log FILE`)

Каждый раунд дописывается в файл plain text (без ANSI). Структура:

```
======================================================================
  Отчёт мониторинга сайтов
  Проверка #1  ·  2026-09-29 00:46:45  ·  время сессии: 10s
======================================================================

[СЕТЬ]
  Локальный IP:   10.8.1.17
  Шлюз:           192.168.1.1  (ping OK  258.6 ms)
  Маршрут:        via 192.168.1.1 dev wlp3s0
  DNS-резолверы:  192.168.1.1
  VPN:            VPN: amn0  IP: 10.8.1.17

[СИСТЕМА]
  OS:           Debian GNU/Linux 13 (trixie)
  Пользователь: alex@debian

[РЕЗУЛЬТАТЫ]  11 UP  /  4 DOWN  из 15
----------------------------------------------------------------------
  [UP ]         200    0.76s  https://pb.combocloud.ru/  ->  194.85.220.4
           DNS: 127.0.0.53 -> 194.85.220.4
           TLS: *.combocloud.ru
  [DOWN]         404    0.35s  https://fs.corpsoft24.ru/  ->  194.126.162.193
           DNS: 127.0.0.53 -> 194.126.162.193
           причина: 404  (server: Microsoft-HTTPAPI/2.0)  |  <!DOCTYPE HTML...
  [DOWN]     timeout   10.01s  https://jira.corpsoft24.ru/  ->  192.168.170.54
           DNS: 127.0.0.53 -> 192.168.170.54
           причина: timeout
  ...
----------------------------------------------------------------------
```

Секции отчёта:

| Секция | Содержимое |
|---|---|
| `[СЕТЬ]` | Локальный IP, шлюз + пинг до шлюза, маршрут, DNS-резолверы, VPN |
| `[СИСТЕМА]` | OS, пользователь@хост |
| `[РЕЗУЛЬТАТЫ]` | URL, IP, HTTP-статус, время, DNS (nslookup), TLS, причина (для DOWN) |
| `[ICMP-ПИНГ]` | RTT и потери (только при `--icmp`) |
| `[ИЗМЕНЕНИЯ]` | up→down / down→up с предыдущей проверки |

## Формат sites.txt

Один URL на строку. Строки с `#` — комментарии. Без схемы добавляется `https://`.

## Требования

- Python 3.10+
- Linux
- `ip` (iproute2) — определение IP интерфейсов, маршрут
- `nslookup` (dnsutils) — для DNS в отчёте
- `resolvectl` (systemd-resolved) — для DNS-резолверов (опционально)
- Для ICMP-пинга: root/CAP_NET_RAW или поддержка ICMP DGRAM
