## 🔴 Исправления (potential bugs / несоответствия)

### 1. `check()`: DNS и TLS выполняются даже при ошибке HTTP
- **Файл:** `app.go`, функция `check()`
- **Проблема:** `result.IPs, result.DNSErr = resolve(ctx, ...)` и `getTLSExpiration(...)` выполняются после `client.Do(req)`, даже если запрос уже завершился ошибкой (timeout, connection refused, invalid URL). Это:
  - тратит время на лишние сетевые вызовы;
  - при `timeout` контекст уже истёк — `resolve` и `getTLSExpiration` гарантированно завершатся с ошибкой контекста, что записывается в `DNSErr`/`TLSErr` как ложная причина недоступности;
  - для невалидного URL `u` может быть `nil` при вызове `u.Hostname()` — **panics** (см. п. 2).
- **Решение:** вынести DNS/TLS в отдельную ветку только когда `u != nil` и `result.Err == nil`; при ошибке запроса — пропустить или явно пометить «не проверено из-за ошибки HTTP».

### 2. `check()`: потенциальный nil-dereference на невалидном URL
- **Файл:** `app.go`, функция `check()`
- **Проблема:** если `parseURL(url)` вернул ошибку, `u` остаётся `nil`, но дальше кода есть `u.Hostname()` и `u.Scheme` — **panic**.
- **Решение:** после `if err != nil { ... return result }` — вернуть результат сразу (это частично уже сделано, но `u` используется дальше — убедиться, что `return` есть в каждом early-exit).

### 3. `isConnectionRefused` — только Linux
- **Файл:** `errors.go`, функция `isConnectionRefused()`
- **Проблема:** `errors.Is(err, syscall.ECONNREFUSED)` работает только на Linux. На macOS/Windows код ошибки другой (`WSAECONNREFUSED` через `net.OpError` или `*os.SyscallError`).
- **Решение:** добавить проверку `*net.OpError` с `Op == "dial"` + `Err` содержит "connection refused", либо использовать `syscall` per-OS.

### 4. `getTLSExpiration` — не учитывает redirect на другой хост
- **Файл:** `tls.go`
- **Проблема:** `http.Client` настроен с `CheckRedirect: ErrUseLastResponse`, то есть redirect не следует. Но если URL `https://hostA` редиректит на `https://hostB`, TLS-сертификат проверяется для `hostA`, а не для финального хоста. Это может дать ложный `OK` или `EXPIRED`.
- **Решение:** после получения ответа с кодом 3xx извлечь `Location` и, при необходимости, проверить TLS для целевого хоста. Либо документировать ограничение.

### 5. `printResult` — TLS не выводится для http:// URL
- **Файл:** `report_text.go`, функция `printResult()`
- **Проблема:** блок TLS выводится только при `u.Scheme == "https"`. Если URL указан как `http://`, но сервер на самом деле принимает HTTPS — информация о сертификате теряется.
- **Решение:** опционально: при `http://` не показывать TLS, но добавить пометку «TLS не проверяется (http)».

### 6. `loadURLs` — нет нормализации схемы
- **Файл:** `input.go`
- **Проблема:** `sites.txt` в корне проекта содержит строку `example.com` (без схемы). `parseURL` отклонит её как invalid URL. Python-версия добавляла `https://` по умолчанию.
- **Решение:** в `loadURLs()` или `parseURL()` добавлять префикс `https://` если схема не указана.
